<decisions>
## Implementation Decisions

### Template strategy
- Customise existing Prestige templates in place (page.about.json, page.contact.json, index.json, etc.) — don't create SP-prefixed alternates
- Existing templates (index, page.about, page.contact) keep their Prestige sections for now — update as SP sections are built in later phases
- New templates that don't exist (page.press, page.careers, collection.portfolio, collection.workshop, product.workshop-item) use Prestige sections as temporary stand-ins — replace with SP sections as they're built
- Journal gets its own dedicated templates: blog.journal.json and article.journal-entry.json (not reusing blog.json/article.json)

### Collection setup
- Portfolio collections (portfolio-all, portfolio-residential, portfolio-commercial, portfolio-hospitality) are empty manual collections used as route shells — URL routing only, project data comes from metaobject queries in section Liquid
- Workshop collections use smart collection conditions based on `workshop.collection_name` metafield — products auto-sort as metafield is populated
- workshop-all created with broad smart condition; 2-3 placeholder sub-collections created now, renamed when client confirms category names
- One template per collection type: collection.portfolio.json for all portfolio-* collections, collection.workshop.json for all workshop-* collections
- Both portfolio and workshop collection templates use minimal chrome (header only, no announcement bar) for an immersive gallery feel

### Metaobject references
- Sections consume metaobject data via Shopify dynamic sources — merchant connects entries through the Customiser's dynamic source picker
- Portfolio grid uses manual control: separate metaobject reference lists per collection page, managed via block-level pickers in the Customiser
- Merchant controls project order via Customiser drag-to-reorder (no sort_order metafield)
- Same project can appear in different positions on different collection pages

### Content population
- Seed demo metaobject entries for development testing (3-4 projects, 2+ team members, 2+ press mentions, 1-2 career openings)
- Workshop products: populate from real content doc at `copy/WORKSHOP (PRODUCT PAGES) - Website Copy Doc.md`
- Projects: populate from real content doc at `copy/PROJECT PAGES - Website Copy Doc.md`
- Team members: populate from real content doc at `copy/ABOUT - Website Copy Doc.md`
- Press accolades and career openings: use placeholder/demo data until client provides content

### Claude's Discretion
- Metaobject type configuration details (display name, access settings)
- Prestige section choices for temporary stand-ins in new templates
- Smart collection condition syntax for workshop metafield filtering
- How to structure the minimal chrome header-group for gallery templates
- Placeholder content text and image choices

</decisions>

<code_context>
## Existing Code Insights

### Reusable Assets
- `templates/page.about.json`, `templates/page.contact.json`: Existing Prestige templates to customise in place
- `templates/collection.json`: Base collection template that can inform collection.portfolio.json and collection.workshop.json structure
- `templates/blog.json`, `templates/article.json`: Prestige blog templates — journal gets separate templates
- `sections/header.liquid`: Header section with full chrome — gallery templates will reference a stripped-down header group

### Established Patterns
- JSON template structure: `sections` object with keyed section references + `order` array
- Header/footer groups: `header-group.json` and `footer-group.json` in `sections/` define site-wide chrome
- Collection template: `main-collection` section handles product grid, filtering, sorting
- Prestige uses `collection.cat-product-list-page.json` and `collection.artist-collection-page.json` as examples of alternate collection templates

### Integration Points
- `config/settings_data.json`: Theme-level settings including colour schemes referenced by templates
- `templates/` directory: Where all template JSON files live
- Shopify Admin: Metaobject types, metafield definitions, and collections are created via Admin API or manual setup — not in theme files

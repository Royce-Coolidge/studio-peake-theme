## 1. Metaobject Definitions in Theme Context

### How metaobjects work in themes (NOT apps)
- This is a **theme project**, not an app. Metaobject types are created **manually in Shopify Admin** (Settings > Custom data > Metaobjects), not via TOML or GraphQL.
- The theme accesses metaobjects via the global `metaobjects` Liquid object: `{{ metaobjects.type.handle }}`
- Field values are accessed by key: `{{ metaobjects.testimonials.homepage.title }}`
- For metaobjects to be accessible in Liquid, the **publishable** capability must be enabled and entries must have **active** status (draft entries return `nil`)
- The **onlineStore** capability enables metaobject theme templates (optional for this phase)

### Section schema: metaobject picker setting
Sections can include a `metaobject` setting type that gives merchants a picker:
```json
{
  "type": "metaobject",
  "id": "my_project",
  "label": "Project",
  "metaobject_type": "project"
}
```
- Returns the metaobject object directly (or blank if no selection)
- `metaobject_type` must match the type handle exactly
- For lists, use `metaobject_list` setting type

### Dynamic sources
- Merchants can connect metaobject fields to section settings via the Customiser's dynamic source picker
- Compatible settings: text, richtext, image_picker, url, video, etc.
- For `metaobject_reference` metafields, the referenced metaobject's fields become available as dynamic sources
- For `list.metaobject_reference`, entries iterate and display the selected field

### Key limitation
- Custom metaobject types are NOT allowed in Shopify Theme Store themes — but this is a private/custom theme, so no restriction applies

## 2. Metafield Definitions for Products

### Creating definitions (theme context)
- Product metafield definitions are created in Shopify Admin: Settings > Custom data > Products > Add definition
- Namespace: `workshop` (merchant-owned, using `custom` namespace pattern)
- Note: The `custom` namespace is Shopify's default for merchant-created definitions. Using `workshop` as namespace is valid for merchant-owned metafields.

### Field types needed
| Key | Type | Notes |
|-----|------|-------|
| tearsheet_pdf | file_reference | Must accept PDF file types |
| secondary_image | file_reference | Must accept image file types |
| room_scheme_images | list.file_reference | List of images for cycling |
| interactive_tags | json | Array of {x_percent, y_percent, label, product_handle} |
| video_url | url | Looping video URL |
| category | single_line_text_field | For filter taxonomy |
| collection_name | single_line_text_field | For smart collection conditions |

### Accessing in Liquid
```liquid
{%- assign tearsheet = product.metafields.workshop.tearsheet_pdf -%}
{%- if tearsheet != blank -%}
  <a href="{{ tearsheet | file_url }}" target="_blank">Tearsheet</a>
{%- endif -%}

{%- assign tags_json = product.metafields.workshop.interactive_tags.value -%}
{%- for tag in tags_json -%}
  <!-- position at tag.x_percent, tag.y_percent -->
{%- endfor -%}
```

## 3. Collection Structure

### Manual vs Smart collections
- **Manual collections**: Merchant manually adds/removes products. Best for: portfolio route shells (empty collections for URL routing)
- **Smart collections**: Products auto-added based on conditions. Best for: workshop collections (match by metafield value)

### Smart collection by metafield
- Smart collections can filter by metafield values in Shopify Admin
- Condition: Product metafield `workshop.collection_name` equals `[value]`
- workshop-all: condition = product type equals "Workshop" (or all products with workshop namespace metafields)
- workshop-[sub]: condition = `workshop.collection_name` equals "[sub-name]"

### Portfolio as route shells
- Create empty manual collections: portfolio-all, portfolio-residential, portfolio-commercial, portfolio-hospitality
- Assign collection.portfolio.json template to all portfolio collections
- Section Liquid queries metaobjects and filters by collection handle:
```liquid
{%- assign current_category = collection.handle | remove: 'portfolio-' -%}
{%- for block in section.blocks -%}
  {%- assign project = block.settings.project -%}
  {%- if current_category == 'all' or project.category.value contains current_category -%}
    <!-- render project card -->
  {%- endif -%}
{%- endfor -%}
```

## 4. Template JSON Structure

### Existing template pattern (from collection.json)
```json
{
  "sections": {
    "section-key": {
      "type": "section-file-name",
      "settings": { ... }
    }
  },
  "order": ["section-key"]
}
```

### New templates to create
| Template | Based on | Prestige stand-in sections |
|----------|----------|---------------------------|
| page.press.json | page.json | main-page (rich text) |
| page.careers.json | page.json | main-page (rich text) |
| collection.portfolio.json | collection.json | collection-banner + main-collection |
| collection.workshop.json | collection.json | collection-banner + main-collection |
| product.workshop-item.json | product.json | main-product |
| blog.journal.json | blog.json | main-blog |
| article.journal-entry.json | article.json | main-article |

### Minimal chrome for gallery templates
The header-group.json contains announcement-bar and header sections in an `order` array. For minimal chrome:
- Create a separate section group file (e.g., `header-group-minimal.json`) that includes only the header section without the announcement bar
- Or use Liquid conditionals in the header-group to hide announcement bar based on template
- Simplest approach: Gallery templates can override by setting announcement bar visibility to false in the template's section group settings

### Template assignment
- Templates are assigned to pages/collections in Shopify Admin
- For collections: Admin > Products > Collections > [collection] > Theme template dropdown
- For pages: Admin > Online Store > Pages > [page] > Theme template dropdown

## 5. Content Population Strategy

### Content docs available
- `copy/WORKSHOP (PRODUCT PAGES) - Website Copy Doc.md` — Workshop product data
- `copy/PROJECT PAGES - Website Copy Doc.md` — Portfolio project data
- `copy/ABOUT - Website Copy Doc.md` — Team member data

### Implementation approach
1. Create metaobject/metafield definitions first (schema only)
2. Create collections and templates
3. Parse content docs to extract structured data
4. Create metaobject entries and products with content from docs
5. Placeholder data for press_accolade and career_opening types

### Metaobject entry creation
- Created in Shopify Admin: Content > Metaobjects > [type] > Add entry
- Or programmatically via Admin API `metaobjectCreate` mutation
- For theme development, Admin UI is the primary creation method
- Each entry needs a unique handle (auto-generated from display_name_field)

## 7. Technical Risks

### Risk: Metaobject field type limitations
- `list.single_line_text` for project categories works but isn't as structured as a dedicated taxonomy
- `json` type for interactive_tags gives flexibility but no schema validation in Admin UI
- **Mitigation**: Document expected JSON structure in metafield description

### Risk: Smart collection metafield filtering
- Smart collection conditions on metafields require the metafield to have a definition (can't filter on ad-hoc metafields)
- **Mitigation**: Ensure `workshop.collection_name` definition exists before creating smart collections

### Risk: Empty portfolio collections
- Empty manual collections may show "no products" messaging from Prestige's main-collection section
- **Mitigation**: Portfolio template sections should not use Prestige's product grid; they query metaobjects instead. The Prestige stand-in will show empty state until replaced by custom sections.

### Risk: Template assignment is manual
- Each collection/page must be manually assigned its template in Shopify Admin
- **Mitigation**: Document the assignment mapping clearly for execution

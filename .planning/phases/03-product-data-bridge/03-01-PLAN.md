<objective>
Wire product data from the product page into the enquiry modal via a JS data bridge.

Purpose: The `product` Liquid object is nil inside overlay group sections. This plan adds data attributes to `main-product.liquid` that emit the product title and featured image URL, then adds JS in the modal section to read those attributes and update the heading, image panel, and a hidden form field. A merchant-selectable fallback image covers non-product pages and products without images.

Output: Two modified Liquid files -- the product page emitting data attributes and the modal consuming them via JS.
</objective>

4. **Add JS data bridge logic.** Inside the existing `DOMContentLoaded` listener (lines 165-181), add the bridge logic BEFORE the existing `dialog:after-hide` listener. Insert after `if (!modal) return;` (line 167):

```javascript
// Product data bridge — read from main-product section data attributes
const productSource = document.querySelector('[data-enquiry-product-title]');
const productTitle = productSource?.dataset.enquiryProductTitle || '';
const imageUrl = productSource?.dataset.enquiryImageUrl || '';

// Update heading
const heading = modal.querySelector('.enquiry-modal__product-heading');
if (heading && productTitle) heading.textContent = productTitle;

// Update hidden field
const hiddenField = modal.querySelector('input[name="contact[Product]"]');
if (hiddenField && productTitle) hiddenField.value = productTitle;

// Update image panel (replace fallback/placeholder with product image)
if (imageUrl) {
  const imagePanel = modal.querySelector('.enquiry-modal__image-panel');
  if (imagePanel) {
    const img = document.createElement('img');
    img.className = 'enquiry-modal__image';
    img.src = imageUrl;
    img.alt = productTitle;
    img.loading = 'eager';
    imagePanel.replaceChildren(img);
  }
}
```

Use `replaceChildren()` instead of `innerHTML` for clarity and safety (per research pitfall 5). Use `textContent` for the heading (not `innerHTML`) since the Liquid `escape` filter already handles encoding.

5. **Add fallback_image setting to schema.** Add an `image_picker` setting to the `settings` array in the schema (after the existing `color_scheme` setting):

```json
{
  "type": "image_picker",
  "id": "fallback_image",
  "label": "Fallback image",
  "info": "Shown when no product image is available"
}
```

Do NOT modify any existing schema blocks or the `enabled_on` configuration.

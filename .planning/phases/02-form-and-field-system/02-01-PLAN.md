  <name>Task 1: Build complete form template with 10 field blocks and schema</name>
  <files>sections/product-enquiry-modal.liquid</files>
  <action>
Replace the placeholder content inside `enquiry-modal__form-content` div with the complete form. Keep the `x-modal` wrapper, `enquiry-modal__layout`, `enquiry-modal__image-panel`, `enquiry-modal__form-panel`, and `dialog-close-button` exactly as they are. Only replace the contents of `enquiry-modal__form-content`.

**Form structure inside enquiry-modal__form-content:**

1. Wrap everything in `{%- form 'contact', class: 'form' -%}...{%- endform -%}`

2. Inside the form tag, use `form.posted_successfully?` conditional:
   - **If posted_successfully:** Show success state div with class `enquiry-modal__success`:
     - `<p class="h2">WE'LL BE IN TOUCH</p>`
     - `<p class="text-subdued">Thank you for your enquiry. We'll get back to you shortly.</p>`
   - **Else:** Show the form fields (error banner + fieldset + submit button)

3. In the else branch (form fields):
   a. **Error banner** (if form.errors):
      ```liquid
      {%- if form.errors -%}
        {%- capture error_content -%}{{ form.errors.translated_fields[form.errors.first] | capitalize }} {{ form.errors.messages[form.errors.first] }}{%- endcapture -%}
        {%- render 'banner', status: 'error', content: error_content -%}
      {%- endif -%}
      ```

   b. **Field rendering with collect-then-render pairing:**
      First pass -- scan blocks to detect which paired fields are present:
      ```liquid
      {%- assign has_first_name = false -%}
      {%- assign has_last_name = false -%}
      {%- assign has_country = false -%}
      {%- assign has_postcode = false -%}
      {%- assign rendered_first_name = false -%}
      {%- assign rendered_last_name = false -%}
      {%- assign rendered_country = false -%}
      {%- assign rendered_postcode = false -%}
      {%- for block in section.blocks -%}
        {%- case block.type -%}
          {%- when 'first_name' -%}{%- assign has_first_name = true -%}
          {%- when 'last_name' -%}{%- assign has_last_name = true -%}
          {%- when 'country' -%}{%- assign has_country = true -%}
          {%- when 'postcode' -%}{%- assign has_postcode = true -%}
        {%- endcase -%}
      {%- endfor -%}
      ```

      Second pass -- render blocks in merchant order. When hitting a paired field for the first time, render the paired row (both fields together). Use `rendered_*` flags to skip the partner when encountered later.

      For **first_name** block: if `has_first_name and has_last_name`, render a `<div class="fieldset-row">` containing both first_name and last_name inputs. Set both `rendered_first_name` and `rendered_last_name` to true. If only first_name is present (no last_name), render it standalone in a plain `<div>`.

      For **last_name** block: same logic in reverse -- if both present and not yet rendered, render the paired row. If only last_name (no first_name), render standalone.

      For **country** block: same pairing pattern with postcode. If both present, render a `<div class="fieldset-row">` with country select + postcode input.

      For **postcode** block: same pairing pattern with country.

      For **email, company, phone, address, notes, marketing**: render standalone, each in a `<div>` with `{{ block.shopify_attributes }}`.

      Field rendering details:
      - first_name: `{%- render 'input', type: 'text', name: 'contact[first_name]', label: 'First Name', value: customer.first_name, autocomplete: 'given-name' -%}`
      - last_name: `{%- render 'input', type: 'text', name: 'contact[last_name]', label: 'Last Name', value: customer.last_name, autocomplete: 'family-name' -%}`
      - email: `{%- render 'input', type: 'email', name: 'contact[email]', label: 'Email Address', value: customer.email, autocomplete: 'email' -%}`
      - company: `{%- render 'input', type: 'text', name: 'contact[company]', label: 'Company Name', autocomplete: 'organization' -%}`
      - phone: `{%- render 'input', type: 'tel', name: 'contact[phone]', label: 'Phone Number', autocomplete: 'tel' -%}`
      - address: `{%- render 'input', type: 'text', name: 'contact[address]', label: 'Address', autocomplete: 'street-address' -%}`
      - country: `{%- render 'select', name: 'contact[country]', label: 'Country', options: all_country_option_tags, show_empty_value: true, autocomplete: 'country' -%}`
      - postcode: `{%- render 'input', type: 'text', name: 'contact[postcode]', label: 'Postcode', autocomplete: 'postal-code' -%}`
      - notes: `{%- render 'input', name: 'contact[body]', label: 'Add Notes', multiline: 4 -%}` (MUST use `contact[body]` not `contact[notes]` -- Shopify maps `contact[body]` to email body)
      - marketing: `{%- render 'checkbox', name: 'contact[marketing]', value: 'yes', label: block.settings.disclaimer_text -%}`

   c. **Submit button** after closing the fieldset div:
      ```liquid
      {%- render 'button', content: 'Submit Enquiry', type: 'submit' -%}
      ```

4. **Add inline script** after closing `</x-modal>` tag, before `{% schema %}`:
   ```html
   <script>
     document.addEventListener('DOMContentLoaded', () => {
       const modal = document.getElementById('enquiry-modal');
       if (!modal) return;
       modal.addEventListener('dialog:after-hide', () => {
         const form = modal.querySelector('form');
         if (form) form.reset();
       });
     });
   </script>
   ```

5. **Update the schema** to add blocks array with all 10 block types. Each block type has `"limit": 1`. Only the `marketing` block has a setting (`disclaimer_text` as richtext with default `"<p>I agree to receive marketing communications from Studio Peake.</p>"`). All other blocks have `"settings": []`.

**What NOT to do:**
- Do NOT modify the x-modal wrapper, image panel, form panel structure, or close button
- Do NOT add HTML5 `required` attributes -- server-side validation only per user decision. Do NOT pass `required: true` to any snippet render call.
- Do NOT add client-side validation JS
- Do NOT add loading/disabled state on submit button
- Do NOT use `contact[notes]` -- use `contact[body]` for the Notes field
- Do NOT make labels editable -- they are hardcoded per user decision
